## Автоматические сценарии

По 16 сценариев в Chromium и Firefox. Браузерные проверки обращались к настоящим API и PostgreSQL; ошибки и задержки отдельных запросов воспроизводились через Playwright route interception. Таймер проверялся с управляемыми браузерными часами.

1. US-01: новая пустая заметка появляется в списке и редакторе; «Личное», «Без названия», пустой текст.
2. US-02: пустой список сопровождается сообщением и работающим действием создания.
3. US-02: открываются заголовок, полный текст и чек-лист; выбор доступен с клавиатуры; данные разных заметок не смешиваются.
4. US-03/04: запрос через 1000 мс, отсутствие запроса до этого, обновление заголовка и текста после перезагрузки, изоляция другой заметки.
5. US-04: до ответа отсутствует «Сохранено»; ввод во время запроса сохраняется следующим запросом.
6. US-04: переход немедленно сохраняет изменения без ожидания таймера.
7. US-04: потеря ответа после записи на сервере сохраняет ввод и позволяет безопасный повтор.
8. US-04: ошибка блокирует переход; проверены «Остаться», «Не сохранять» и успешный повтор перед переходом.
9. US-10: пробельный пункт запрещён, добавление кнопкой и Enter, независимые отметки, установка и снятие, восстановление обоих состояний после перезагрузки.
10. US-01/04: повтор создания после потери ответа сохраняет введённый текст без дубликата.
11. US-02: ошибка открытия и успешный повтор.
12. US-04: новый ввод сбрасывает таймер; отправляются последние значения через секунду новой паузы.
13. US-02: поздний ответ открытия не заменяет последнюю выбранную заметку.
14. US-04: новый выбор во время повтора сохранения определяет конечный переход; последние изменения сохранены.
15. US-10: Enter соблюдает тот же предел 500 пунктов, что и кнопка добавления.
16. API: пустой заголовок нормализуется; неверные пункты, повторяющиеся ID и превышение длины отклоняются без изменения записи; другая заметка не меняется; отсутствующая возвращает 404; проверены точные пути и HTTP-методы OpenAPI.

## Исправления при проверке

- Устранён обход ограничения 500 пунктов через Enter, приводивший к ошибке автосохранения.
- Устранён устаревший переход после повтора сохранения, если пользователь уже выбрал другую заметку.
- Тестовый скрипт проверяет сохранность чек-листа и отметок при перезапусках; адрес API для тестов настраивается через `E2E_API_URL`.
- README и описание области приведены к текущим US-01–04 и US-10; удалены устаревшие утверждения о ручном сохранении и отсутствии чек-листа.

## Проверка второго спринта

19 ноября 2026 года прошли 84 проверки. Проверены все 28 сценариев в Chromium 141.0.7390.37, Firefox 142.0.1 и Chrome for Testing 156.0.8078.4. Новые сценарии проверяют перенос с автосохранением, совместную фильтрацию по блокноту и тегу, поиск по заголовку и по тексту чек-листа, восстановление с тегами и защиту от дубликатов при параллельных запросах.

Тесты работали с отдельным PostgreSQL 18 в Docker Desktop. Среда Docker располагала 12 логическими процессорами и 3,8 ГиБ оперативной памяти. Сервер, Nginx и браузер работали на одном компьютере, соединение шло через loopback. Для проверки НФ-03 создали отдельный блокнот с 1000 заметок примерно по 1,7 тыс. символов каждая.

| 1000 совпадений | 124 мс | 179 мс |
| Одно совпадение в пункте чек-листа | 32 мс | 62 мс |
| Нет совпадений | 30 мс | — |

Заметка сохранила заголовок, текст, версию и исходный ключ создания при перезапуске и пересоздании Backend и PostgreSQL.
