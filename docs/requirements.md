# Первая версия: область реализации

Актуальный источник требований — критерии первой версии, перечисленные пользователем 17 ноября 2026 года. Реализуются только US-01, US-02, US-03, US-04 и US-10. Исходные документы `Отчет_ТРПО_Agile.pdf` и `Mini_Evernote_Agile_8_Slides_Final.pptx` использовались ранее для требований и оформления; актуальные критерии ниже имеют приоритет.

| История | Критерии и реализация |
| --- | --- |
| US-01. Создание | «Новая заметка» сразу отправляет POST; после подтверждения запись выделена в списке и открыта в редакторе. Единственный блокнот — «Личное». Сервер заменяет пустой или пробельный заголовок на «Без названия». Пустой текст допустим. |
| US-02. Список и открытие | GET списка возвращает карточки; выбор загружает заголовок, полный текст и чек-лист отдельным GET. Пустой список содержит сообщение и действие создания. PostgreSQL и постоянный volume сохраняют записи между открытиями приложения. Поздний ответ предыдущего открытия не меняет текущий выбор. |
| US-03. Редактирование | Редактор изменяет заголовок и текст выбранной записи. PUT обновляет только эту заметку, сохраняя ID, блокнот и дату создания. После подтверждения и перезагрузки видны новые значения. |
| US-04. Автосохранение | Таймер сбрасывается при каждом изменении; через 1000 мс после последнего ввода отправляется текущий черновик. Одновременно выполняется один запрос записи; последующий ввод сохраняется отдельно. «Сохранено» видно только после ответа сервера и при отсутствии новых изменений. Ошибка сохраняет ввод и показывает действие повтора. |
| US-04. Переход | Выбор другой заметки или создание новой немедленно отправляет изменения. Переход ждёт подтверждения всех текущих правок. При ошибке диалог блокирует переход до успешного повтора или явного «Не сохранять»; «Остаться» сохраняет ввод в редакторе. |
| US-10. Чек-лист | Кнопка или Enter добавляет пункт с непустым после обрезки пробелов текстом. Отметки устанавливаются и снимаются независимо. Массив пунктов и отметки входят в автосохранение и восстанавливаются после перезагрузки. |

## API и хранение

Пользовательский API ограничен GET/POST `/api/notes` и GET/PUT `/api/notes/{id}`. Полная заметка содержит `checklist`: упорядоченный массив `{ id, text, isCompleted }`. Пункты хранятся в PostgreSQL, миграция `AddChecklist` дополняет исходную схему без удаления заметок. Swagger, OpenAPI и healthcheck служат технической диагностике.

Повтор создания использует один UUID и неизменный исходный POST; введённые до подтверждения изменения затем отправляются PUT той же заметки. Это предотвращает дублирование после потери ответа. Черновик хранится отдельно от последнего подтверждённого состояния. PUT передаёт версию заметки. Если другая вкладка сохранила более новую версию, сервер отклоняет устаревшую запись. Редактор оставляет черновик, пока пользователь явно не откажется от него. Повтор создания сравнивается с исходным запросом независимо от последующих правок.

Технические ограничения: заголовок — до 200 символов, текст — до 100 000, пункт — до 1000, список — до 500 пунктов с уникальными внутри заметки UUID. UI и сервер проверяют эти ограничения; пробельный пункт не добавляется.

## Вне области

Другие пользовательские истории не реализованы: создание и выбор других блокнотов, теги, поиск, удаление заметок, корзина, редактирование и удаление пунктов чек-листа. Также отсутствуют регистрация, совместное редактирование, автономное сохранение и публикация. В интерфейсе нет действий или заглушек для этих функций; демонстрационные заметки автоматически не создаются.
